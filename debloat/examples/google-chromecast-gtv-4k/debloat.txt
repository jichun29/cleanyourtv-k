# Google TV 14 (SDK 34), build UTTC.250917.004 (14193937)
#
# Apply:   TV_HOST=<ip> tools/disable.sh examples/google-chromecast-gtv-4k/debloat.txt
# Undo:    TV_HOST=<ip> tools/restore.sh examples/google-chromecast-gtv-4k/debloat.txt com.google.android.apps.tv.launcherx
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Stock launcher: com.google.android.apps.tv.launcherx. No Live TV app and no HDMI inputs (it's a dongle):
# leave live_tv_package empty in config.xml.
#
# Known quirks on this firmware:
# - ADB on port 5555 is closed (connection refused) until you pair once through Wireless debugging with
#   the stock adb: Developer options > Wireless debugging > Pair device with pairing code, `adb pair
#   <ip:pairport> <code>`, `adb connect <ip:connectport>` (`adb mdns services` lists both ports), then
#   `adb tcpip 5555`. After that tools/tv.py works on 5555 (README, Troubleshooting).
# - `cmd package set-home-activity com.gathin.tvhome` returns Success but launcherx stays the default.
#   Disable BOTH com.google.android.apps.tv.launcherx and com.google.android.tungsten.setupwraith
#   (setupwraith re-enables launcherx), only after the new launcher is installed.
# - Disabling setupwraith also breaks casting from phones, reported on the Chromecast HD on the same
#   build (#361). The Cast receiver (com.google.android.apps.mediashell) reads its factory device
#   credentials from a provider inside setupwraith
#   (com.google.android.libraries.tv.setupwraith.libs.castinfo.CastInfoProvider), so once the wizard
#   is gone and the device has rebooted, YouTube on the phone answers "Untrusted device ... couldn't
#   be verified" and the receiver logs "No private key, hence empty signature" every minute. Keeping
#   the provider while taking Home away does not work: pm disable-user on
#   setupwraith/.RecoveryActivity is refused with a SecurityException. Either debloat only (keep
#   launcherx and setupwraith enabled), or re-enable setupwraith after each boot, wait a minute for
#   "Created singleton instance of ClientAuthSigner" in logcat, then disable it again - the receiver
#   holds the credentials in memory, so casting works until the next reboot
#   (docs/TROUBLESHOOTING.md, "Casting fails with Untrusted device").
# - With launcherx disabled the YouTube button on the remote does nothing. It sends BUTTON_3
#   (keycode 190). Button Mapper only remaps added buttons in its paid Pro version; Key Mapper
#   (open source, keymapperorg/KeyMapper) does it for free. Play Store lists Key Mapper as incompatible
#   with this device, so install the -foss APK from its GitHub releases, then over ADB:
#   pm grant io.github.sds100.keymapper android.permission.WRITE_SECURE_SETTINGS
#   settings put secure enabled_accessibility_services io.github.sds100.keymapper/io.github.sds100.keymapper.system.accessibility.MyAccessibilityService
#   Map trigger "Button 3" (short press) to action "Launch app > YouTube". Record the trigger with the
#   physical remote: keys injected with `input keyevent 190` don't reach Key Mapper, and D-pad presses
#   made while recording get added to the trigger.
# - com.google.android.tvrecommendations and com.google.android.apps.education.cast2class ship
#   disabled at the factory; `pm disable-user` on them fails with "Shell cannot change component
#   state". Don't add them to a restore list either.
# - Disabling dreamx leaves screensaver_components pointing at it. Point it at the launcher's clock:
#   settings put secure screensaver_components com.gathin.tvhome/.ClockDream
# - Animation scales already ship at 0.5x on this build.
#

# Play Services, Gboard, Bluetooth, com.google.android.tv.dfuservice (remote firmware updates).

# (see the setupwraith quirks above).
